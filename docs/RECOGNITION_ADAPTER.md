# 本地视觉识别适配与上线边界

## 1. 当前交付能力

当前源码完整实现：

- 任意上传视频的扩展名、大小、H.264/AAC、时长和媒体可读性校验；
- FIFO 队列、失败重试、服务重启恢复；
- 从多个视频帧自动搜索显示屏候选区域，再逐秒抽帧做七段码模板 OCR；
- 彩色/复杂显示屏使用本地 Tesseract 离线回退；
- 9 个稳定段读数、量程/单位换算、设备档案匹配，以及带显示屏框的真实识别帧；
- 缺次、顺序、不稳定、超限、量程错误的复算判定；
- 人工修正、提交、复核、撤回、作废、审计和导出。

显示屏数字 OCR 和二维码解码在本地运行。按当前产品决策，本版本暂不实现 ASR；
“清洁”“水平调节”“内部校正是否通过”由检验人员现场观察确认。无法形成可信
示值的任务进入“待人工处理”，不会生成虚假读数。

默认无需配置显示屏坐标。自动搜索会结合设备标称点校验候选区域；固定机位可用
`DISPLAY_REGION=x,y,width,height` 覆盖。无法形成可信区域或示值时任务待人工处理。

## 2. 适配器接口

`src/services/analyzer.js` 默认导出 `analyzeVideo(context)`。正式模型适配器需
保持以下返回：

```json
{
  "engine": "tesseract.js-7.0.0 + seven-segment-template",
  "personCard": {"account": "U001", "conf": null, "evidence": {"frameCount": 3}},
  "deviceCard": {"code": "F001", "conf": null, "evidence": {"frameCount": 6}},
  "deviceId": "F001",
  "durationSeconds": 392.1,
  "rangeSwitch": true,
  "readouts": [
    {
      "point": 0,
      "idx": 1,
      "value": 200.0009,
      "unit": "g",
      "off": 32,
      "time": "2026-10-26 08:32",
      "conf": 0.99,
      "stable": true,
      "range": 1,
      "recognizedText": "200.0009 g",
      "bbox": {
        "x": 0.1195,
        "y": 0.6510,
        "width": 0.7537,
        "height": 0.1198,
        "coordinateSpace": "normalized-video-frame"
      },
      "frame": {
        "offsetSeconds": 40,
        "time": "2026-10-26 08:31",
        "displayText": "200.0009 g",
        "source": "video-frame",
        "marked": true
      },
      "screenshot": "screenshots/<record>/I1-1.jpg"
    }
  ],
  "screenshots": [],
  "warnings": []
}
```

未知字段可以附加，但上述字段不得删除或改名。模型进程必须本地运行，不得产生
外网请求或遥测。

`bbox` 使用整帧归一化坐标；`offsetSeconds` 必须是该截图实际抽取的视频绝对秒数。
分析器会拒绝缺失识别框、帧偏移越界、帧内文本无法解析，或 `mg/g` 换算后与记录
数值不一致的结果。生成的截图会在显示屏区域绘制黄色边框，详情页可直接打开
“识别帧核验”并跳转至对应视频位置。

## 3. 建议处理流水线

1. FFprobe 校验流、时长和编码。
2. 用本地 `jsQR` 扫描视频前 40 秒的人员卡与设备卡；支持同帧多码检测、遮挡后
   继续解码和跨抽样帧身份合并。卡面缺失、重复、未知或与登录人员/读数设备冲突
   时不得生成自动正式记录。
3. 从多帧自动搜索显示区，再做透视校正、去反光、二值化/多帧投票。
4. 检测稳定段；每个平台段至少 3 秒、变化不超过 1 个 d，取最后有效读数。
5. 按时间保留全部称重段；九项展示数据取每组前三次，完整时序用于顺序、重复和
   额外读数判定。二维码 `conf` 不写固定概率，改为保存解码次数与帧证据。
6. 双量程检测切换段，把前 3 次归入高量程，后 6 次归入低量程。
7. 保存裁切前原始帧、黄色显示区识别框、时间偏移、帧内文本、模型版本、参数和置信度。
8. 调用 `evaluateRecord` 生成结论，并把结论、原因、容差、规则版本和时间写入固定
   判定快照；模型适配器不得自行改判。

## 4. CPU 和内存约束

- 不要求 GPU。
- 分析服务持续 CPU 宜不超过 2 核。
- 同一时刻仅一个分析进程。
- 单段 5 分钟视频目标分析时间不超过 20 分钟。
- 模型加载应常驻或使用受控工作进程，避免每个任务重复初始化。
- 超时、显存/内存不足和文件损坏必须落成可读错误码。

## 5. 验收门槛

必须使用客户按附录 B 重新采集的样本统计：

- 9 个示值字段级准确率 ≥ 98%；
- 人员卡和设备卡二维码成功率 ≥ 99%；
- 人员卡与设备卡同屏时的多码检测成功率和身份唯一性；
- 未达标字段 100% 标记低置信；
- 判定结论在输入正确前提下 100% 正确；
- 3 段样例结果为 2 通过、1 不通过。

识别准确率不能只用当前三段示例推导，也不能用人工修正后的值冒充模型原始值。
